# DoorKey — BLE 귀가 감지 자동 문열림

```
폰(아이폰·갤럭시) ──BLE 광고(RPA)──> ESP32-S3 (현관 안쪽)
                                      │ 등록 때 받은 IRK로 "누구 폰인지" 해석
                                      │ 외출 → 귀가 판정
                                      └─HTTPS──> SmartThings API ──> 도어락 unlock
```

- 아이폰은 **앱이 필요 없습니다.** 한 번 블루투스 페어링해서 신원 키(IRK)만 넘겨주면 됩니다.
- 갤럭시는 평소 광고가 드물 수 있어서 **DoorKey 비컨 앱**으로 광고를 계속 켜 둡니다. 앱에는 비밀값이 없고, 폰의 IRK로 만든 주소를 ESP가 해석합니다.
- 모드 및 루틴·가상 스위치·Rule을 거치지 않고 ESP가 도어락 unlock을 직접 호출합니다.

```
firmware/DoorKey/         ESP32-S3 Arduino 스케치
android/DoorKeyBeacon/    갤럭시용 광고 앱 (Android Studio)
```

## 1. 펌웨어 올리기 (Arduino IDE)

**보드 매니저**: `esp32` by Espressif **3.1.0** (실사용 확인)
- 3.3.11에서는 `iram0_0_seg overflowed by 960 bytes` 링크 에러로 빌드 실패
- 코어 버전을 바꾸면 도구 메뉴 값(Flash Size, PSRAM, Partition)이 초기화되니 아래 표대로 다시 맞출 것

**라이브러리 매니저**
- `NimBLE-Arduino` by h2zero — 2.x (2.5.1로 확인)
- `ArduinoJson` by Benoit Blanchon — 7.x (7.4.2로 확인)

**도구 메뉴**

| 항목 | 값 |
|---|---|
| 보드 | ESP32S3 Dev Module |
| Flash Size | 16MB (128Mb) |
| PSRAM | OPI PSRAM |
| Partition Scheme | 16M Flash (3MB APP/9.9MB FATFS) |
| USB CDC On Boot | 보드의 USB 포트로 연결하면 Enabled, COM 포트면 Disabled |

첫 부팅 때 **DoorKey-Setup** AP(비밀번호 `doorkey1234`)가 뜹니다. 폰으로 붙어서 `http://192.168.4.1` → 시스템 탭에서 Wi-Fi를 넣으면 재부팅됩니다. **2.4GHz만 가능**하고, 5GHz SSID는 접속되지 않습니다. 직접 빌드할 때는 `config.h`의 `DEFAULT_WIFI_SSID/PASS`에 적어도 됩니다 (공개 저장소에는 커밋하지 마세요).

접속: `http://doorkey.local` 또는 시리얼 로그에 찍힌 IP. 로그인 `admin` / `doorkey` → **시스템 탭에서 바로 비밀번호 변경**.

이후 업데이트는 USB 없이 됩니다: 웹 UI › 시스템 › 펌웨어 업데이트 (아래 **10. 펌웨어 업데이트** 참고).

컴파일 없이 USB로 굽기: [esptool-js](https://espressif.github.io/esptool-js/)에서 `0xE000` ← `boot_app0.bin`, `0x10000` ← `DoorKey.bin`(릴리스) 또는 `_ota.bin`(firmware 브랜치). **Erase Flash는 누르지 마세요** (등록 기기·토큰이 지워짐).

**설치 위치**: 현관문 안쪽, 도어락 근처 콘센트에 USB 전원. 금속 현관문에 바짝 붙이기보다 30cm쯤 떨어뜨리는 게 신호가 고릅니다.

## 2. SmartThings 연결 (한 번만)

PAT는 24시간이면 만료돼서 OAuth 앱을 만들어야 합니다. ESP가 토큰을 스스로 갱신합니다.

1. SmartThings CLI 설치: `npm install -g @smartthings/cli` (또는 GitHub SmartThingsCommunity/smartthings-cli 릴리스)
2. `smartthings apps:create` 실행
   - 앱 종류: **OAuth-In App**
   - 이름/설명: 아무거나 (예: DoorKey)
   - Scopes: **`r:devices:*`, `x:devices:*`**
   - Redirect URI: **`https://httpbin.org/get`**
3. 출력된 **OAuth Client ID / Client Secret**을 웹 UI › SmartThings › 1번에 입력하고 저장 (Secret은 다시 볼 수 없으니 따로 보관)
4. 2번의 **인증 페이지 열기** → 삼성 계정 로그인 → 위치(집) 선택 → 허용
5. httpbin 페이지로 넘어가면 **주소창 URL 전체**(또는 화면의 JSON)를 복사해 붙여넣고 **토큰 발급**
6. 상태 카드에서 **연결 확인** → HTTP 200이면 토큰과 Device ID가 맞습니다
7. **문 열기 테스트** → 현관이 열리는지, "요청 ○○ms"가 얼마인지 확인

3번 카드의 기본값은 작성자 집 도어락 값입니다. 자기 도어락의 Device ID·Capability·Command로 바꾸세요.
직접 호출이 403 등으로 거부되면 **가상 스위치**를 만들어 Rule로 도어락을 열게 하고, Device ID = 가상 스위치, Capability = `switch`, Command = `on`으로 바꾸세요 (약 1초 더 걸림).

리프레시 토큰이 무효가 되면(장기간 전원 꺼짐 등) 웹 UI에 빨간 배너가 뜨고, 알림 URL을 설정해 두면 폰으로도 옵니다. 4~5번만 다시 하면 됩니다.

## 3. 폰 등록

웹 UI › 기기 › 이름 입력 › **등록 시작** (2분간 "DoorKey" 키보드로 보임)

- **아이폰**: 설정 › Bluetooth › 기타 기기 › DoorKey › 페어링
- **갤럭시**: 설정 › 연결 › 블루투스 › 스캔 › DoorKey › 등록

"등록 완료"가 뜨면 폰 블루투스 목록의 DoorKey는 삭제해도 됩니다.
표시된 **기기 주소**가 폰의 블루투스 주소(아이폰: 설정 › 일반 › 정보 / 갤럭시: 설정 › 휴대전화 정보 › 상태 정보)와 같은지 확인하세요. 등록 2분 동안 근처의 다른 폰이 끼어들 수 있기 때문입니다.

## 4. 갤럭시 비컨 앱

`android/DoorKeyBeacon`을 Android Studio에서 엽니다.

**Gradle을 새로 받지 않습니다.** AGP 8.7.3 / Kotlin 2.0.21 / Gradle 8.9이고, 외부 라이브러리가 하나도 없습니다(Compose도 안 씀). Gradle wrapper(jar 포함)도 들어 있어서 wrapper 생성 단계도 없습니다. Sync는 캐시에서 바로 끝나야 정상입니다.

Build › Build APK(s) 또는 USB 디버깅으로 바로 Run.

앱에서:
1. **권한 허용** (블루투스 광고, 알림)
2. **배터리 최적화 제외**
3. 삼성 설정 › 배터리 › 백그라운드 사용 제한 › **절전 예외 앱**에 추가 (One UI 버전에 따라 메뉴 이름이 조금 다름)
4. **비컨 켜기** → 상태가 "광고 중"
5. 웹 UI › 기기 › **갤럭시 앱 비컨**이 "해석됨 (이름)"이면 끝

"미해석"으로 나오면 그 폰을 아직 등록하지 않았거나, 폰이 IRK 기반이 아닌 주소로 광고하는 경우입니다. 후자라면 로그와 함께 알려주세요.


## 5. 현장 튜닝 (처음 며칠)

현황 탭의 그래프(최근 60초 RSSI)와 숫자를 보면서 맞춥니다. 점선 두 개가 귀가/이탈 기준입니다.

| 재볼 곳 | 볼 값 | 맞출 설정 |
|---|---|---|
| 엘리베이터 앞, 폰 주머니 | RSSI | **귀가 RSSI**: 이 값보다 5~10 낮게 |
| 현관 밖 문 닫고 서 있을 때 | RSSI | **이탈 RSSI**: 이 값보다 조금 낮게 |
| 가장 먼 방 (폰 둔 채) | RSSI, 신호 끊김 여부 | 이탈 RSSI가 이 값보다 **높아야** 함 |
| 하루 정도 집에 있을 때 | **최대 공백** | **부재 판정**: 최대 공백보다 넉넉히 길게 |
| 귀가 후 로그 | "감지 후 ○○ms" | 문 앞 대기 시간 |

폰별 "간격"과 "최대 공백"이 핵심 지표입니다. 아이폰이 잠금 상태에서 광고를 얼마나 자주 하는지는 기기·iOS 버전마다 달라서 실측 전에는 알 수 없습니다. 최대 공백이 부재 판정보다 길면 집 안에서 "외출"로 오판할 수 있습니다.

## 6. 판정 규칙

```
미확인 ──감지──> 재실
재실 ──[부재 판정]초 동안 미감지──┬─ 사라지기 직전 최대 RSSI ≥ 이탈 RSSI ──> 외출 (현관으로 나감)
                                 └─ 그보다 약함 ──────────────────────────> 신호 끊김 (집 안, 무장 안 함)
신호 끊김 ──감지──> 재실 (안 열림)
외출 ──귀가 RSSI 이상 감지──> 재실 + 문 열기
     단, 아래면 문을 열지 않고 재실로만 바꿈
     - 외출이 [최소 외출]보다 짧음
     - 외출 전에 보던 BLE 주소가 그대로 나타남 (재생 공격 방지)
     - 자동 개방 꺼짐 / 허용 시간대 아님 / 쿨다운 중
```

- 부팅(또는 등록·재활성화) 뒤 한 번도 안 보인 폰은 [최소 외출] 시간이 지나면 외출로 봅니다. 정전 후 복구돼도 귀가 때 열립니다.
- 폰 BLE 주소는 약 15분마다 바뀝니다. **재생 공격 방지**가 켜져 있으면 15분 안쪽의 짧은 외출에서는 안 열릴 수 있습니다. 그땐 태그 버튼을 쓰거나, 이 옵션을 끄세요.
- 외출 중인 사람이 있으면 SmartThings와 TLS 연결을 미리 열어 둡니다(연결 미리 유지). 귀가 순간 핸드셰이크(보통 1초 안팎)를 건너뜁니다. SmartThings 탭에서 "평균 유지 시간"이 너무 짧게 나오면 효과가 적으니 꺼도 됩니다.

## 7. 보안 메모

- **폰을 가진 사람 = 열쇠**입니다. 폰 잠금은 필수입니다.
- BLE 근접 방식은 **릴레이 공격**(폰 근처와 현관에서 신호를 실시간 중계)을 원리적으로 막지 못합니다. 차량 디지털키가 UWB로 옮겨간 이유와 같습니다. 도어락의 자동 재잠금이 노출 시간을 줄여 줍니다.
- 녹화해 둔 주소를 나중에 틀어주는 **재생 공격**은 위의 "재생 공격 방지"로 막습니다.
- 웹 UI 비밀번호, 삼성 계정 2단계 인증, ntfy 토픽 이름(추측 어려운 값)을 챙기세요.
- 백업 파일과 ESP 플래시에는 IRK와 토큰이 들어 있습니다. 백업 파일은 안전한 곳에 보관하세요.
- SmartThings·ntfy HTTPS 연결은 `setInsecure()`로 서버 인증서 검증을 생략합니다(암호화는 유지). 같은 Wi-Fi에 침입한 공격자의 중간자 공격에는 취약합니다.

## 8. 알림 (선택)

ntfy 앱 설치 → 추측하기 어려운 토픽 구독 → 웹 UI › 시스템 › 알림에 `https://ntfy.sh/그-토픽` 입력.
문이 열릴 때, 문 열기 실패, 인증 만료 시 알림이 옵니다.

## 9. 확인한 것 / 못 한 것

확인함
- 실사용: esp32 3.1.0 + NimBLE-Arduino 2.5.1 + ArduinoJson 7.4.2, 귀가 감지 → 문 열림 동작 (요청 약 1.9초, 연결 유지 전)
- 펌웨어 업데이트 서명: GitHub Actions에서 서명 → 내장 공개키로 검증하는 흐름을 PC에서 모의 확인 (기기 설치는 실기기 확인 필요)
- RPA 해석 함수: 블루투스 코어 스펙 부록의 테스트 벡터와 일치
- 귀가 판정 로직: PC에서 11개 시나리오(외출·귀가, 짧은 외출, 재생 공격, 집 안 신호 끊김, 약한 신호, 수동 전환 경합, 등록 직후, 동시 귀가 쿨다운, 자동 개방 꺼짐) 시뮬레이션 통과
- 웹 UI: 가짜 데이터로 띄워서 스크립트 오류 없음 확인
- 안드로이드 앱: Android API 35 기준으로 Kotlin 컴파일 통과

실기기에서 확인 필요
- 아이폰·갤럭시의 실제 광고 간격과 RSSI (5번 튜닝)
- 갤럭시 앱 광고가 IRK로 해석되는지 ("해석됨" 표시)
- SmartThings OAuth 토큰으로 도어락 커스텀 capability 직접 호출이 허용되는지 (안 되면 가상 스위치)
- Gradle 전체 빌드(이 환경에서는 Android SDK를 받을 수 없어 Kotlin 컴파일까지만 확인)

## 10. 펌웨어 업데이트

**기기 쪽**
- 12시간마다(부팅 3분 뒤 첫 확인) 이 저장소의 최신 릴리스를 확인합니다. 새 버전이 있으면 ntfy로 한 번 알리고, 웹 UI 상단에 안내가 뜹니다.
- 웹 UI › 시스템 › 펌웨어 업데이트에서 **설치**를 누르면 받아서 설치하고 재부팅합니다 (1분 정도, 그동안 귀가 감지·문 열기 멈춤).
- 설치 전에 확인하는 것: `manifest.json`의 ECDSA P-256 서명(펌웨어에 내장된 공개키 `OtaKey.h`), 현재보다 높은 버전인지, 받은 파일의 크기·SHA-256.
- 새 버전으로 부팅한 뒤 Wi-Fi에 붙은 상태로 90초가 지나야 "정상"으로 확정합니다. 그 전에 3번 넘게 재부팅하거나 5분 안에 Wi-Fi에 못 붙으면 이전 버전으로 되돌리고, 되돌린 버전이 ntfy로 알립니다.
- 웹 UI로 bin 파일을 직접 올려도 같은 롤백이 적용됩니다.

**릴리스 만들기**
1. `config.h`의 `FW_VERSION`을 올리고 `main`에 커밋·push
2. 배포: `git push origin main:release` (또는 같은 버전의 태그 `git tag v1.0.4 && git push origin v1.0.4`)
3. Actions가 빌드 → `manifest.json` 서명 → 릴리스 `v버전`(`DoorKey.bin`, `manifest.json`, `manifest.sig`, `boot_app0.bin`) 생성. 같은 버전 릴리스가 이미 있으면 실패합니다.

서명용 비밀키는 저장소 Settings › Secrets and variables › Actions의 `OTA_SIGNING_KEY`에만 있습니다. 공개키는 `firmware/ota_pub.pem`과 `firmware/DoorKey/OtaKey.h`(내용 동일).

**주의**
- GitHub 계정을 가진 사람 = 펌웨어를 바꿀 수 있는 사람 = 현관문을 열 수 있는 사람입니다. **2단계 인증 필수.**
- 키를 바꾸려면: 새 키 쌍을 만들고 `OtaKey.h`·`ota_pub.pem`을 바꾼 펌웨어를 **기존 키로 서명해 한 번 배포**한 뒤 secret을 교체합니다.
- `main`에 push만 해서는 기기에 배포되지 않습니다. `release` 브랜치 push나 태그로 만든 릴리스만 배포됩니다.
